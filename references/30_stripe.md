# 30 Stripe（タスク7）

目的：お金を受け取る。**支払いリンク（Payment Links）**を使う＝コード不要・Stripe の画面で作る（公式：コードを記述せずに決済を受け付ける）。

早い道（本人はテスト用の制限付きキーを貼るだけ・AI が商品と支払いリンクを API で作る）は `25_hayamichi.md`。「検証中」の間はこの 30 を使う。

## 順番（ここが大事）
Stripe は本番で決済を有効にする前に「**事業内容と販売条件が分かる Web サイトの URL**」を求める。
だから **先に 40_hanbai_joken.md（特商法・販売条件ページ）を公開**してから Stripe の本人確認に進む。
審査待ちの間にアプリ本体（タスク8）を進める。

## 1. アカウント（本人）
1. `https://dashboard.stripe.com/register` → メール・氏名・パスワード。
2. メール確認 → 電話番号の確認（SMS）。
- 終わると：ダッシュボード（**テスト環境**の表示）が開く。

## 2. 本人確認・事業情報（本人のみ・AI は手伝えない）
1. ダッシュボードの「本番環境を有効にする」→ 事業の種類（個人事業主／法人）・氏名・住所・生年月日・業種・**Web サイト URL**（販売条件ページの公開 URL）・入金先の銀行口座。
2. 本人確認書類の撮影はスマホの方が楽。
3. 送ると審査になる。`state/PROGRESS.md` を `審査待ち` にする。追加資料を求められたら本人が対応。
- AI が代わりに同意・入力・提出をしてはいけない。

## 3. 商品と支払いリンク（本人・画面）
1. 左メニュー **商品カタログ** → **商品を追加** → 名前・説明・**価格（税込で一つ）**・**一回限り**（継続はこのキットの範囲外）。
2. **支払いリンク** → **新規作成** → さっきの商品 → **メールアドレスを収集**（既定）→ 「支払い後」より下の **詳細設定** で「利用規約への同意を求める」を ON にし、利用規約の URL に `https://<公開URL>/terms`・**カスタムテキスト**に「引き渡し時期：◯◯／返品・キャンセル：◯◯（特定商取引法に基づく表記 https://<公開URL>/tokushoho）」を書く（特商法 12条の6：申込の最終画面に分量・価格・支払時期・引渡時期・取消条件を出す。全商品に適用）→ **リンクを作成**。
3. 「支払い後」の設定：**確認ページ** に「購入後の案内」（50_teikyo.md で決めた文）を書く。または「別の URL にリダイレクト」で `https://<公開URL>/thanks` を指定。
4. できた `https://buy.stripe.com/...` を AI に貼る（公開 URL なので貼ってよい。**パラメータ無しの素のリンク**）。
- **テスト環境のリンクと本番のリンクは別物**。本番有効化の後に **本番環境** で作り直す。

## 4. AI がやる
1. `src/index.js` の `STRIPE_LINK` を本番リンクに置き換え、販売ページのボタンにする。
2. `state/PROGRESS.md` の記録にリンクを書く。
3. 通し確認は **テスト環境**で：本人が Stripe を「テスト環境」に切り替えて同じ商品・支払いリンクを作り、AI が一時的にそのリンクで公開 → 本人がテストカード `4242 4242 4242 4242`（期限は未来・CVC 任意）で通す → Stripe のテスト環境の **支払い** に出る → 本番リンクに戻す。本番で自分で買うのは返金しても手数料が戻らず、規約上も勧めない。

## 決まり
- Stripe の API 鍵（`sk_live_...`／`sk_test_...`）はこのキットでは**使わない**。支払いリンクだけ。
- 自動で商品を渡す（Webhook）に進む時は、鍵が要る。その時は 50_teikyo.md の「自動提供」を読み、鍵は Cloudflare の **Settings → Variables and Secrets** に本人が入れる（AI の環境には入れない）。
- 特商法 12条の6 は**全ての通信販売の申込画面**が対象。Stripe の Checkout 画面に引渡時期と取消条件が出るよう、上の 2 の「利用規約への同意」と「カスタムテキスト」を必ず設定する。
